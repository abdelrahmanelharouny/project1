    81→    81→# 2. GLOBAL ENGINEERING RULES
    82→    82→
    83→    83→These rules apply to every workstream.
    84→    84→
    85→    85→## Evidence integrity
    86→    86→
    87→    87→Every observation must retain:
    88→    88→
    89→    89→- Source/provider.
    90→    90→- Acquisition timestamp.
    91→    91→- Observation or forecast period.
    92→    92→- Spatial resolution.
    93→    93→- Units.
    94→    94→- Geographic coverage.
    95→    95→- Processing method.
    96→    96→- Quality flags.
    97→    97→- Missing-data status.
    98→    98→- Provenance.
    99→    99→- Whether the value is observed, derived, forecast, projected, estimated, or synthetic.
   100→   100→
   101→   101→Never mix observed, forecast, projected, and synthetic data without explicit classification.
   102→   102→
   103→   103→Synthetic data must never be represented as real satellite or climate observations.
   104→   104→
   105→   105→## Scientific integrity
   106→   106→
   107→   107→- Use established scientific methods and documented formulas.
   108→   108→- Preserve original measurements.
   109→   109→- Record assumptions and uncertainty.
   110→   110→- Never invent missing observations.
   111→   111→- Do not infer field-level precision beyond source resolution.
   112→   112→- Distinguish correlation from causation.
   113→   113→- Never claim a model is scientifically validated without independent validation.
   114→   114→- Make unsupported outputs unavailable rather than presenting false precision.
   115→   115→
   116→   116→## Architecture
   117→   117→
   118→   118→Preserve:
   119→   119→
   120→   120→Data Providers → Normalization → Evidence Store → Feature Engine → Agronomic Engines → Scenario Intelligence → Recommendation Registry → Presentation → Feedback.
   121→   121→
   122→   122→Every recommendation must continue flowing through the centralized registry.
   123→   123→
   124→   124→## Database safety

   127→   127→- Preserve existing farm, field, observation, recommendation, scenario, and feedback data.

   129→   129→- Never drop production tables.
   130→   130→- Do not perform destructive migrations.
   131→   131→- Test migrations on isolated databases.
   132→   132→- Verify migration upgrade and downgrade behavior.
   133→   133→- Preserve tenant isolation.
   134→   134→
   135→   135→## Implementation quality

   138→   138→- Avoid duplicate providers.
