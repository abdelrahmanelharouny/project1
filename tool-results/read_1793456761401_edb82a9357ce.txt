    54→# 2. EXECUTION PHILOSOPHY
    55→
    56→Apply the following principles throughout the work.
    57→
    58→## 2.1 Evidence over assumptions
    59→
    60→Every scientific claim, formula, crop property, and decision rule must have identifiable evidence.
    61→
    62→Distinguish:
    63→
    64→- Direct field measurement.
    65→- Laboratory measurement.
    66→- Farmer-reported information.
    67→- Satellite-derived estimate.
    68→- Climate reanalysis.
    69→- Statistical model prediction.
    70→- Published reference value.
    71→- Expert-validated local rule.
    72→- Synthetic testing data.
    73→
    74→These evidence types must never be silently treated as interchangeable.
    75→
    76→## 2.2 Scientific accuracy over apparent completeness
    77→
    78→A missing value is preferable to a fabricated agricultural recommendation.
    79→
    80→A system that correctly reports insufficient evidence is better than a system that always produces a confident-looking answer.
    81→
    82→## 2.3 Reproducibility
    83→
    84→Every feature calculation, candidate assessment, optimization run, and comparison must be reproducible using:
    85→
    86→- Input data snapshot.
    87→- Data source and product versions.
    88→- Knowledge pack version.
    89→- Feature specification version.
    90→- Algorithm version.
    91→- Configuration.
    92→- Relevant calculation assumptions.
    93→
    94→## 2.4 Global architecture, locally validated decisions
    95→
    96→Global software support does not imply universal agronomic validity.
    97→
    98→Every regional recommendation must be supported by locally applicable crop knowledge, calendars, environmental evidence, and relevant constraints.
    99→
   100→## 2.5 Implementation discipline
   101→
   102→Inspect first, document findings, define corrections, then implement incrementally.
   103→
   104→Preserve existing APIs and data wherever possible.
   105→
   106→Introduce additive migrations and explicit version changes for scientific or algorithmic changes.
   107→
   108→Do not silently change the meaning of existing features or scores.

   213→Review:

   229→
   230→- Soil property concentration.
   231→- Soil property stock.
   232→- Volumetric measurements.
   233→- Gravimetric measurements.
   234→- Prediction uncertainty.
   235→- Measurement uncertainty.
   236→
   237→Specifically verify Soil Organic Carbon:
   238→
   239→A concentration value in g/kg is not an organic-carbon stock in t/ha.
   240→
   241→Calculating stocks may require soil depth, bulk density, coarse fragments, and appropriate spatial assumptions.
   242→
   243→Do not derive a root-zone profile from a single 0–5 cm layer.
   244→
   245→### Spatial aggregation requirements
   246→
   247→Investigate whether the current field extraction method should support fractional pixel-area weighting instead of relying exclusively on all-touched or center-based inclusion.

   253→For SoilGrids prediction quantiles, investigate appropriate uncertainty propagation when aggregating several pixels to a field.
   254→
   255→Do not simply average per-pixel lower and upper quantiles and automatically label the results as a formal 90% field-level prediction interval.

   769→- Regional time zones.
   770→- Crop-season calendars.
   771→
   772→Use appropriate equal-area methods when comparing field areas or calculating area-weighted environmental features.
   773→
   774→Preserve native spatial resolution and source geometry.
   775→
   776→A Global system must not claim field-level precision that the underlying raster dataset cannot support.
   777→
   778→Agricultural calendars must support actual locally defined seasons rather than relying only on hemisphere-based seasonal assumptions.
   779→
   780→# 10. PHASE H — SCIENTIFIC BENCHMARKING AND TESTING
   781→
   782→The existing 314-test history is a baseline, not a substitute for independent scientific validation.
   783→
   784→Build a Scientific Benchmark Suite.
   785→
   786→## 10.1 Golden numerical tests
   787→
   788→For each important formula:
   789→
   790→- Define a documented reference case.
   791→- Calculate an independently verified expected result.
   792→- Compare implementation output.
   793→- Test unit conversions.
   794→- Test boundary conditions.
   795→- Test numerical tolerances.
   796→- Explain the source of the expected result.
   797→
   798→Where possible, use official worked examples or independently implemented reference calculations.
   799→
   800→## 10.2 Property-based tests
   801→
   802→Test mathematical properties, not only fixed examples.
   803→
   804→Examples:
   805→
   806→- Increasing effective rainfall under unchanged assumptions must not increase net irrigation demand.
   807→- Increasing available water allocation must not make a previously feasible strategy infeasible solely because of that change.
   808→- Invalid hard constraints must never be silently relaxed.
   809→- A dominated strategy must never appear as non-dominated.
   810→- Unit conversions must preserve physical quantities.
   811→- Identical input snapshots and configurations should reproduce identical deterministic outputs.
   812→
   813→These properties must be qualified by the assumptions of the underlying calculation.
   814→
   815→## 10.3 Metamorphic testing
   816→
   817→Test system behavior when:
   818→
   819→- Units change but physical quantities remain equivalent.
   820→- Polygon coordinates are transformed into another valid CRS.
   821→- Records are reordered.
   822→- Irrelevant observations are added.
   823→- Missing intervals are introduced.
   824→- Data products are switched.
   825→- Knowledge pack versions change.
   826→- Optimization weights change.
   827→
   828→## 10.4 Cross-component integration
   829→
   830→Validate that:
   831→
   832→- Provenance survives every processing stage.
   833→- Feature snapshots reference correct observations.
   834→- Knowledge versions are attached to evaluations.
   835→- Optimization runs preserve the correct feature snapshots.
   836→- Frontend labels match backend meanings.
   837→- Synthetic data never masquerades as measured evidence.
   838→- Tenant isolation remains enforced.
   839→
   840→## 10.5 Performance and operational validation
   841→
   842→Review:
   843→
   844→- Large field datasets.
   845→- Many years of observations.
   846→- Raster extraction memory usage.
   847→- Background job reliability.
   848→- Database query patterns.
   849→- Spatial index usage.
   850→- API pagination.
   851→- Retry behavior.
   852→- Provider health degradation.
   853→- Long-running optimization jobs.
   854→
   855→Do not introduce unnecessary infrastructure or distributed services without a demonstrated need.
   856→
