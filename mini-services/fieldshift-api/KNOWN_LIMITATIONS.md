# Known Limitations

**Current status: 2026-11-14, remediation branch `remediation/legacy-hardening`.** This register is based on the current checkout and the checks listed in [`docs/implementation/REMEDIATION_STATUS_2026-11-14.md`](../../docs/implementation/REMEDIATION_STATUS_2026-11-14.md). Passing unit tests and mocked transports do not establish database, multi-process, production, or live-provider readiness. The earlier [master audit](../../docs/MASTER_REPOSITORY_AUDIT.md) and [milestone report](../../docs/implementation/MASTER_AUDIT_MILESTONE_2026-11-14.md) remain the pre-remediation baseline.

## Identity, authorization, tenancy, and billing

- Non-development registration no longer returns an access/refresh session before email verification; access-token resolution and refresh also reject unverified accounts. Development mode remains a separate convenience path. There is no production email-delivery adapter, so an operator must provide a safe verification-delivery workflow before onboarding non-development users.
- Legacy farm-member create/update/remove paths now require the exact owner role, and legacy member creation applies the resolved organization-seat limit. Invitation acceptance also applies the Free/paid seat limit. API-level regression cases were added, but the PostGIS-backed integration suite was not run in this environment.
- Logout resolves the bearer token or session cookie and revokes its full access/refresh family; refresh rotation is serialized. Database-backed access/refresh/session-reuse checks still need to run in CI with PostgreSQL/PostGIS.
- Missing paid subscriptions now resolve to catalog Free entitlements in the changed farm/field, report, organization-seat, and public-API-key paths. API keys require the plan's API enablement and current rate entitlement; zero is not silently converted to a positive rate. Route-level tenant, quota, rotation, expiration, and revocation coverage remains incomplete.
- Report creation rejects a field that does not belong to the selected farm, and report payload gathering constrains the field to both farm and organization when both selectors are present. This is not a complete audit of every identifier-bearing endpoint, cache, conversation, evidence assembler, or background operation; organization selection and tenant isolation need broader API tests.
- Billing remains a sandbox-only adapter. Production startup fails closed because no real production provider exists and also requires an explicit strong webhook secret. Sandbox event signatures reject stale/future timestamps, and successful payment processing checks the referenced open invoice's amount and currency. No real payment provider or live money movement is implemented or verified.
- Outbound webhook destinations now reject non-global/private address targets, resolve and pin public DNS answers, and disable redirects; plain HTTP is limited to local development. Unit coverage uses mocked transports/resolution, not a deployed egress boundary. Webhook signing secrets are still stored recoverably in plaintext in the database; encrypt or externalize them before relying on tenant-managed webhooks in production.

## Observation ingestion and provenance

- CSV parsing normalizes header keys, handles BOM-prefixed input, hashes the exact uploaded bytes, and rejects non-finite values. Canonical observation DTOs validate finite measurements and uncertainty, missing/null invariants, and period ordering. Ingestion uses per-row savepoints so a duplicate/integrity failure does not roll back earlier accepted observations. Parser and pure contract tests pass; PostgreSQL persistence and GeoTIFF upload paths were not executed here.
- Coverage distinguishes quality states and counts only non-null observations marked `valid` as usable coverage. The API does not yet provide a complete cross-provider taxonomy for stale, conflicting, questionable, rejected, and missing evidence or a universal policy for reconciling duplicates and revisions.
- Provider coverage, request identifiers, raw references, and other provenance are not all durably preserved for every provider result. Units, geometry/CRS, time-support compatibility, provider-specific quality masks, and retention policies still require provider-by-provider verification.
- Synthetic fixtures, historical reanalysis, satellite-derived products, provider estimates, farmer-entered observations, and reference knowledge must remain clearly distinct. No live source-health check was performed for NASA Earthdata/CDSE, SoilGrids, Open-Meteo, CHIRPS, S3, or LLM services.

## Background jobs and operations

- The `background_jobs` table is now the durable source of truth. Each process has a local wake-up queue, but workers poll persisted queued jobs and claim work with a database row lock. Built-in replay executors register before startup recovery; recovery handles queued and stale work with a bounded retry count and a configurable stale threshold. These cross-process, restart, lock, and failure paths have **not** been exercised against a live PostgreSQL/PostGIS service in this environment.
- Raster-processing submission still requires an end-to-end transaction-ordering check: the generic queue row must not become visible to a worker before the associated raster-domain job commits. The GIS-owned processing service was not changed on this branch. Duplicate execution, idempotency, crash windows, and domain/generic status reconciliation require database-backed multi-worker tests before claiming operational reliability.
- A database poller is not a managed broker or lease service. API/worker deployment still needs supervised workers, database capacity limits, retry monitoring, cancellation policy, and safe behavior under long-running jobs. Scenario, sensitivity, robust-rotation, and decision-document workloads may still execute synchronously.
- Rate-limit, scheduler, circuit-breaker, narrative-cache, and some metrics state remains process-local; there is no production-grade telemetry exporter or cross-replica aggregation. `/metrics` still requires network-level protection.

## Agronomic and decision-engine limits

- Active knowledge-pack crop rows now supply their own traits, windows, and water parameters instead of mixing rows from losing versions. Numeric trait calculations use the same country-specific value that explanations resolve, with global fallback only when no exact regional value exists. Seed-pack values remain reference material until expert regional review; no rule is treated as locally confirmed by default.
- Crop suitability is not a yield forecast. Seasonal precipitation is no longer compared directly to an annual reference range as though the periods matched. Missing critical climate/calendar evidence is exposed as unevaluated; secondary missing dimensions remain explicit and can make an assessment conditional. These are screening outputs, not local agronomic prescriptions.
- Weighted rotation steering pools season-dependent scores across the planning horizon rather than reusing only the first season. Criteria with incomplete candidate/season evidence are omitted rather than zero-filled, with a reason recorded. Soil-health scores use sourced numeric root-depth and nitrogen-fixation traits only; absent numeric evidence is unevaluated. Crop-family, nutrient, pest/disease, historical, and water constraints are binding only where the corresponding supported data and validation rules permit.
- Robust-rotation and portfolio objectives still include documented proxy/steering components; post-hoc explanatory metrics and solver objectives are not interchangeable. Review the solver weights, objective aggregation, and user-facing explanations before treating a ranking as a complete multi-objective agronomic conclusion.
- Knowledge values, coarse calendars, and climate proxies are not locally calibrated. The system does not estimate crop prices, yield, or universal prescriptions. Soil-health indicators are not measured stock changes; missing data is not interpreted as poor soil.
- Climate projections and weather-forecast scenarios are unavailable. Scenario ET0 is not recalculated from transformed weather variables. Vegetation stress context still needs strict temporal alignment, and sparse forecast dates must not be interpreted as consecutive dry days.

## Satellite, raster, and external-provider readiness

- **No direct NASA HLS, Sentinel-2/CDSE, CHIRPS, SoilGrids, Open-Meteo, or S3 implementation was changed or live-verified by this remediation branch.** A separate GIS workstream owns direct satellite/raster changes. HLS discovery and protected asset reads in source do not prove acquisition correctness: the direct path still requires Fmask/cloud-shadow propagation, field-CRS reprojection, field-windowed raster reads, pixel alignment, clipping, nodata, and source-lineage verification. The separate P05 preprocessing path is not evidence that the direct HLS path works.
- Open-Meteo is a historical ERA5/ERA5-Land archive, not a weather forecast. CHIRPS is operator-supplied GeoTIFF input. SoilGrids WCS, Sentinel-2/CDSE, NASA Earthdata, and external storage depend on current provider availability, credentials, and egress; current readiness is unknown.
- Local and S3-compatible storage code exists, but the sandbox/Compose deployment has no production bucket, KMS, IAM, lifecycle, retention, backup, or end-to-end durability verification. Production object-storage readiness is an operator/deployment task.

## AI, generated text, and evaluation

- Field briefs now use a fail-closed per-sentence citation and same-unit numeric gate against the cited evidence section, with one constrained retry and deterministic fallback. This gate is conservative and is not a complete semantic entailment proof; it does not perform unit conversions.
- Recommendation narratives still lack the same runtime evidence contract. Advisor Q&A's numeric matcher remains screening-grade and can compare a claim against facts from the wrong evidence domain or unit; the `kg/ha`/`Mg/ha` conversion has a known factor error. Prompt delimiter escaping and trusted/untrusted metadata separation also remain incomplete.
- The LLM bridge is optional and single-provider. No provider router/fallback, durable token/cost accounting, tool executor, current live-provider success, or document RAG system was established. Curated structured packs and deterministic/statistical analytics are not vector-indexed document retrieval or a trained predictive model.
- Narrative cache fingerprints and single-flight behavior need work. Feedback is not an automatic retraining signal; agricultural calibration requires controlled evaluation and expert review.

## Frontend, deployment, and release evidence

- The frontend's navigation/map/analytics helper suite passes locally and TypeScript checks pass. There is still no rendered-route/browser, accessibility, cross-organization switching, or Arabic RTL visual verification in this checkpoint. Empty/error states and organization selection need broader end-to-end coverage.
- The repository-root Compose file is a local/demo topology, not production deployment. It was statically reviewed; no container was started. It does not provision production TLS, fixed ingress, managed secrets, persistent artifacts, coordinated workers, monitoring, backup, or recovery drills.
- No PostgreSQL/PostGIS service, Docker runtime, migration run, database integration suite, CI hosted job, or live provider was available/run for this checkpoint. Ruff was not installed. These are explicit verification gaps, not passing checks.
