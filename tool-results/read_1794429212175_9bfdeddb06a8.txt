     1→"""P3 commercial SaaS platform models.
     2→
     3→Additive schema layer for: subscription/billing/entitlements (W2), org
     4→invitations + activity timeline (W3), notifications + reports (W5), public
     5→API keys + outgoing webhooks (W6), onboarding + user preferences (W1/W7).
     6→
     7→Design rules honored here (P3 §12):
     8→- Every tenant-scoped table carries organization_id with an FK + index so
     9→  tenant isolation is enforceable at the query layer.
    10→- Idempotency: billing_events has a unique (provider, provider_event_id);
    11→  webhook_deliveries has a unique (endpoint_id, event_id, attempt).
    12→- No raw card data is ever stored — the provider layer keeps only opaque
    13→  provider references.
    14→- Money is stored as integer minor units (cents) + ISO currency code; no
    15→  floats for money.
    16→"""
