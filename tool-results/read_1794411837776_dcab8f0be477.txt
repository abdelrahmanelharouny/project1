     1→"""ORM models for the P2 advanced agricultural intelligence expansion.
     2→
     3→P2 workstreams (conventions mirror app/db/models.py, models_m6bc_m7.py and
     4→models_ai.py: UUID PKs, TimestampMixin for mutable tables, JSONB with python
     5→defaults, additive-only migrations):
     6→
     7→- `satellite_scenes` (A) — scene-level provenance for satellite imagery used
     8→  by vegetation intelligence. One row per (field, provider, scene); index
     9→  values themselves live in `observations` (variable codes ndvi/evi/...,
    10→  evidence_class=satellite_derived_estimate) so the platform has exactly one
    11→  observation store.
    12→- `weather_forecasts` (B) — forecast evidence. Deliberately NOT in
    13→  `observations`: forecasts are issued estimates with issue time + valid time
    14→  + horizon, and mixing them with historical observations would overwrite the
    15→  observed record. One row per (field, provider, model, variable, issue,
    16→  valid, horizon); immutable once written.
    17→- `forecast_verifications` (B) — aggregate forecast-vs-observation verification
    18→  (bias/MAE/RMSE) per horizon bucket; only written when paired data exists.
    19→- `climate_projection_records` (B) — long-term projections preserving model id,
    20→  scenario id, ensemble size, bias-correction status and uncertainty bands.
    21→  Never treated as deterministic future weather.
    22→- `soil_state_snapshots` (C) — immutable, checksummed longitudinal soil state
    23→  (measured + estimated variables at depths, with per-value evidence class).
    24→- `soil_change_estimates` (C) — conservative modeled change between two
    25→  snapshots (mass-balance / trajectory), carrying assumptions + model version;
    26→  estimated, never presented as measured improvement.
    27→- `rotation_stress_runs` (D) — Rotation Failure Lab executions: candidate
    28→  rotations × stress packs, robustness metrics, constraint violations,
    29→  reproducible via pinned inputs + checksum.
    30→- `evidence_gap_reports` (E) — append-only snapshots of detected evidence gaps
    31→  with importance and decision impact.
    32→- `evidence_acquisition_actions` / `evidence_acquisition_events` (E) —
    33→  lifecycle of evidence acquisition suggestions (append-only event history).
    34→- `portfolio_runs` / `portfolio_allocations` (F) — farm-level CP-SAT portfolio
    35→  optimization: per-field × season × crop area allocation under shared
    36→  resource constraints, with explicit trade-offs vs independent field plans.
    37→
    38→Tenant isolation follows the existing pattern: rows are scoped through
    39→field_id / farm_id and the API layer resolves field → farm → organization via
    40→`get_field_for_principal` / `get_farm_for_principal`. No org_id column on
    41→domain tables (consistent with soil/water/scenario tables).
