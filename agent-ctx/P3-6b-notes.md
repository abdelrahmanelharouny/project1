## Org resolution (shared convention with 6-a)

Every tab resolves the active organization via `GET /api/v1/orgs` (function `listMyOrganizations`), TanStack key **`['p3-orgs']` — identical to TeamTab's cache, same payload shape**, so switching tabs never refetches and org data stays consistent across spheres. `items[0]` (oldest active, server-sorted) is the active org. Empty list ⇒ the shared "No organization yet" empty state whose CTA calls `useCropTwistUi.getState().setActiveTab('team')`.

## Endpoints used (verified against `app/api/v1/{billing,analytics,reports,developer}.py`, `app/billing/{service,entitlements}.py`, `app/analytics/service.py`, `app/reports/{service,contracts}.py`, `app/publicapi/{api_keys,webhooks}.py`)

## Component behavior highlights

- **BillingTab**: subscription card (plan name, status Badge colored per state `active/trialing/past_due/grace/canceled`, period start/end, trial/grace ends, provider+mode, amber **Test mode** badge inferred from `subscription.provider === 'sandbox' || provider_mode === 'test'`, cancel-at-period-end badge) with cancel (AlertDialog: stays active until period end, data kept) and resume actions. Plans grid from the public catalog: monthly/yearly Switch, yearly shows "Save N%" **only when both prices exist and the math is positive**; entitlement list per plan with Check/X (bool) and value/`Unlimited` (int, -1); "Current plan" outline state; start vs change dialog chosen by whether a live subscription exists (canceled ⇒ start again; server Conflict surfaces honestly otherwise). Enterprise plans (`amount_cents === null`) render a mailto **Contact sales** button with an explanatory tooltip — never a fake price. Usage section = `GET /billing/usage` per-metric Progress bars (`used of limit`; unlimited ⇒ label instead of a bar; limit 0 renders honestly as 0) + reset-period note; entitlements list from `GET /billing/entitlements`. Invoices: desktop table + stacked mobile cards, `Intl.NumberFormat` money from `amount_cents`/`currency_code` (never computed), status badges open/paid/void. Sandbox panel renders **only** when the subscription payload says test provider; a 403/422 from `/billing/sandbox/pay` permanently hides the panel for the session (server is the source of truth); outcome Select succeed/decline; success/decline toasts.
- **InsightsTab**: filter bar (farm Select from `useFarms`, season text, date range, Apply/Reset) plus a **disabled crop input with a tooltip** — the dashboard endpoint 400s on crop/date filters by design (`_reject_unsupported`), so the filter is disabled instead of being silently sent or silently ignored. KPI row maps the API `metrics` array generically (key→i18n label, fallback = server label); every tile shows value+unit (units suppressed for `count`/`ratio`, the latter via `pct()`), provenance Badge (observed=emerald, model_derived=stone, simulated=amber, missing=muted — each with a tooltip definition), period, and the server `note` behind an Info tooltip. Missing metrics (value null / provenance missing) render the dashed **No data** chip with tooltip "No observations for this period" — never zeros. Crop distribution = Recharts vertical BarChart of API `crop_distribution` only (empty ⇒ No data panel). Recommendations/adoption (acceptance rate + by-state chips + verbatim server note) and data freshness (per-variable counts, last observation, fresh/stale/very_stale/No-data chips). Farm performance (enabled by farm+dates): metric tiles, field comparison table (+mobile cards), water volumes — precipitation total from the API with its verbatim note, irrigation always shown as the API's `missing` block. Commercial metrics: user-supplied water price (m³) + currency inputs committed **on blur** (no per-keystroke refetch), API metric tiles, collapsible **Assumptions** rendered verbatim (`key: value` monospace) + the API `honesty_note`. Benchmarks: farm/field scope Select, entries table, metric definitions, compatibility note, and the muted "cross-organization benchmarks are a future capability" note (matches `cross_org_anonymized.provenance: missing`).
- **ReportsTab**: generate form — 10 types (mirrors `contracts.REPORT_TYPES`), pdf/xlsx/csv, en/ar, scope Select (whole organization or a farm), date range (defaults: trailing 30 days), "instant" Checkbox (auto-disabled for pdf), optional recurrence (none/weekly/monthly ⇒ `schedule` 7/30 after create). `sync=true` responses with `status=succeeded` auto-download; `failed` surfaces the exact `job.error`. Library: status Badges (queued/running pulse dots, succeeded, failed, expired), failed rows show the API error string (tooltip on desktop, inline text on mobile), size from `file_size_bytes` (B/KB/MB formatting only), created/next-run/repeat metadata; actions Download (blob + server filename), Regenerate, Schedule dialog (`interval_days|null`), Delete confirm. While any row is queued/running the list query **re-polls every 3s** (see deviation 4). Desktop table + stacked cards.
- **DeveloperTab**: keys — create dialog (name + scope Checkboxes fed by `GET /developer/events.scopes`), plaintext secret shown **once** in a shared SecretOnce dialog with Copy; list (prefix monospace `dir=ltr`, scope badges with tooltip descriptions, last-used relative to server timestamps, revoked badge) with Rotate (confirm ⇒ new secret shown once) and Revoke (confirm). Webhooks — create dialog (https URL + event Checkboxes from `GET /developer/events.events` + optional description), per-endpoint card: enabled Switch (PATCH), consecutive-failures/auto-disabled badges from the server fields, secret rotate (shows once), delete confirm, expandable deliveries panel (auto-polls every 5s while any delivery is pending): event, delivered/pending/failed/dead badges, response code, attempt #, timestamp, verbatim `last_error`, Redeliver button on failed/dead. Usage card: plan rate limit (or Unlimited), `api_enabled` warning badge, per-key totals **summed from the API's daily counters** + each key's snapshot throttle, verbatim rate-limit note. Event reference: catalog from the API; descriptions are i18n copy keyed by event name (unknown future events render the raw name — no invented description).

## Deviations / decisions (worth knowing)

1. **Task text vs backend (analytics filters)**: the dashboard endpoint rejects `crop`/`date_from`/`date_to` with 400 (`_reject_unsupported`), so the crop filter is rendered disabled with an explanatory tooltip and dates apply to farm-performance / commercial-metrics / benchmarks only (where they are required parameters).
2. **Task text vs backend (commercial metrics)**: the API returns exactly `water_volume_m3`, `water_cost`, `cost_per_hectare`, `yield` (the last two always `missing`) — "financial exposure" and "potential savings" tiles from the task text have **no API source** and were not fabricated; the API's metric array is rendered generically so future metrics appear automatically.
3. **Billing scope**: `POST /reports` cannot take an explicit `organization_id` (the Pydantic model has no such field; the service resolves a single-membership org implicitly), so the "Whole organization" scope omits ids and multi-org users scoped to org level see the server's ValidationFailed honestly; farm scoping always works.
4. **Report polling**: the task said poll `GET /reports/{id}` per queued/running row; implemented as a list-level 3s `refetchInterval` while any row is queued/running (same freshness, one request instead of N). Deliveries panel does poll its own endpoint (5s while pending).
5. **Sandbox visibility**: the panel appears only when the subscription payload itself says sandbox/test (`provider`/`provider_mode`), per the task's "infer from subscription payload"; the defensive 403/422→hide rule covers the no-subscription and non-sandbox-provider cases (nothing renders rather than a broken control).
6. **Entitlement catalog keys** are a fixed client map (`ENTITLEMENT_KEYS`) mirroring `app/billing/entitlements.py` keys; unknown future keys are simply not displayed (server still enforces them).
7. `p3b` was already registered in `src/i18n/config.ts`; no edits to `api.ts`, `store.ts`, `i18n/*`, `nav.json`, `workspace.tsx`, 6-a files, or `mini-services/`. Note for the integrator: `workspace.tsx` must import the four default-exported tabs into TabsContent `team/billing/insights/reports/developer` (out of my ownership).
8. Pre-existing backend observation (not mine to fix): `app/api/v1/orgs.py` `_oldest_active_org_id` has a syntax error (`active =  for m in ...`); it is dead code (unused by the routes), but worth flagging to the backend owners.
