FieldShift Security Architecture
Defense in depth on a single origin — identity, authorization, audit and transport controls, with refresh-token reuse detected and revoked
Identity & Access
short-lived sessions, hardened credentials
Password hashing
PBKDF2-HMAC-SHA256 at 600,000 iterations with a per-user salt. The iteration count is embedded in every stored hash, so rising work factors re-hash transparently at next login.
Access token
Bearer JSON Web Token with a 12-hour lifetime; carries the caller’s identity and workspace context on every request.
Refresh token rotation
30-day refresh tokens rotate on every use. Presenting a retired token is treated as theft: the entire token family is revoked.
Account lockout
5 consecutive failed logins lock the account for 15 minutes; the lockout window is advertised to the client.
Authentication rate limiting
Sliding-window limit of 10 requests per minute on authentication endpoints, per client — dependency-free and enforced in-process.
Recovery & verification tokens
Single-use, time-boxed tokens: password reset expires in 1 hour, email verification in 24 hours; both are consumed on first use.
Authorization
Per-farm membership RBAC
Authority derives from farm membership in four ordered roles: owner > manager > agronomist > viewer. The same account may hold different roles on different farms.
Tenant isolation in the service layer
Every query is scoped to the caller’s farms before it reaches the database; viewers are read-only across all modules.
Audit & Traceability
AuditEvent records
Append-only trail of login success and failure, token refresh, refresh-reuse detection, role changes and password events.
Request correlation
x-request-id is propagated from the gateway through the API into logs, error payloads and background jobs.
Transport & Configuration
Same-origin gateway
SPA and API are served behind one gateway origin; the API port is never directly exposed.
CORS allow-list & upload guard
Cross-origin access limited to approved origins; request bodies capped at 32 MB for CSV and GeoTIFF imports.
Configuration hygiene
All settings read from FIELDSHIFT_*-prefixed environment variables; development mode is explicitly off by default.
Token lifecycle under attack — sequence
1
Login
Credentials verified over HTTPS; lockout and rate limit guard the endpoint.
2
Tokens issued
Access token (12 h) plus refresh token (30 d) forming one rotation family.
3
401 received
Access token expires mid-session; the API rejects the request.
4
Refresh & retry
Client redeems the refresh token once and replays the failed request.
5
Reuse detected
A refresh token that was already rotated is presented again.
6
Family revoked
All descendant tokens are invalidated; re-login is required and the event is audited.
