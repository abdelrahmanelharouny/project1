FieldShift Decision Intelligence Pipeline
From observed truth to defensible recommendations — six stages, each adding one layer of trust
STAGE 1Freeze the truth — authoritative baselineField State Baseline
Immutable field snapshot
Observed data only — boundaries, observations, soil, water. Content-locked with snapshot checksum.
Honest gap reporting
Missing capabilities are reported explicitly as unknown — never disguised as poor health or fabricated values.
STAGE 2Pose the question — scenario definitionsScenario Governance
historical_observed
Evidence class: observed. What actually happened on the field.
hypothetical what-if / intervention
Evidence class: hypothetical. Plausible futures built on the baseline.
climate / forecast (contract-only)
Evidence class: not_available — can never reach a finalized status. No fabricated projections.
Lineage & immutability
Restricting foreign keys protect the scenario lineage; a database trigger freezes finalized scenarios, and every scenario type is bound to its evidence class at the database level.
STAGE 3Run the world — scenario executionScenario Execution Engine
Execution runs
Executes a scenario against its parent field-state baseline with the same engines used for observed reality — results are directly comparable.
Derived observations & features
Outputs become scenario-derived observations + feature values, comparable with observed data.
STAGE 4Stress-test the answersSensitivity Analysis  +  Robust Planning
One-at-a-time + 2-D grids
OAT responses per feature; two-factor grid cells and summaries expose interaction effects.
Uncertainty register
A structured uncertainty register records explicit confidence context for every evaluation.
Robust strategies (optimization)
Rotation strategies optimized across whole scenario sets with constraint programming, ranked by worst-case evaluation.
STAGE 5Decide with evidenceDecision Comparisons
Side-by-side comparisons
Strategies and scenarios compared on shared metrics with generated explanations.
Requirements ladder
Each comparison records which data requirements were satisfied, partial, or missing.
STAGE 6Earn trust — validate & documentDigital Twin  +  Data Passport
Digital twin validations
Re-simulate known history and measure divergence between predicted and observed reality.
Data Passport
Every result ships with provenance, completeness, engine versions and honest gaps.
